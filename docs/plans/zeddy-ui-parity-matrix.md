# Zeddy UI capability parity matrix

This matrix assigns an implementation owner and verification path to every region in the Zeddy v3 mockup and every Zed capability that the replacement shell must preserve. The design authority is [`zeddy-agent-workspace-v3.png`](../mockups/zeddy-agent-workspace-v3.png), and the implementation sequence is in [`zeddy-ui-replacement.md`](zeddy-ui-replacement.md).

No row permits a Cargo dependency change. `script/check-zeddy-dependency-baseline` must pass on every branch in the stack.

## Action and keymap inventory

The action names below are compatibility contracts. Implementations may move their controls, but must not silently remove their dispatch paths. `M`, `L`, and `W` mean the authoritative platform files `assets/keymaps/default-macos.json`, `assets/keymaps/default-linux.json`, and `assets/keymaps/default-windows.json`. “Unbound” means that no dedicated default binding is required: the exact action remains dispatchable from the command palette, named menu, or contextual control. Menu dispatch is assembled in `crates/zed/src/zed/app_menus.rs`.
